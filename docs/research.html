RESEARCH / LEARNING AGENDA

Security questions.
Evidence-led answers.

My current interests sit at the intersection of defensive cybersecurity, secure software engineering, and applied computing. This page describes an evolving learning agenda, not a claim of published academic research.

01 / DEFENSIVE SECURITY

Detection engineering & incident response

Understanding how useful security signals emerge from endpoint, network, and application telemetry, and how analysts can move from an alert to a defensible incident assessment.

  • Network traffic analysis and event correlation
  • Behavioral anomalies and threat-path reasoning
  • Evidence preservation, timelines, and incident documentation
02 / SECURE SOFTWARE

Application security & source-code auditing

Reviewing application trust boundaries and security-critical flows to identify weaknesses before deployment, with emphasis on reproducible reasoning and actionable fixes.

  • Authentication, authorization, and object-level access control
  • Input validation, injection surfaces, and API security
  • Secrets, dependency risks, and secure configuration
  • Manual verification, severity assessment, and remediation
03 / AI SECURITY

AI-enabled systems & data boundaries

Exploring security implications of AI-enabled applications, especially data isolation, retrieval boundaries, prompt handling, and misuse-resistant design.

  • Cross-user data separation and authorization context
  • Retrieval-augmented generation trust boundaries
  • Abuse cases, threat modeling, and defensive controls
04 / APPLIED CRYPTOGRAPHY

Cryptographic implementation

Connecting cryptographic theory to implementation decisions, including key derivation, authenticated encryption, integrity, and safe handling of user data.

  • Authenticated encryption and nonce/IV requirements
  • Hash functions and integrity verification
  • Implementation pitfalls and practical cryptographic hygiene
METHOD / WORKING PRINCIPLES

How I approach a security question

Define scope and authorization first. Trace the relevant data and trust boundaries. Validate observations with the least intrusive method available. Record evidence and limitations. Communicate impact and practical remediation responsibly. No unauthorized access, persistence, or hack-back.
